# Technology strategy

## Six principles guide every tech choice
Layout: hexagons
- Guest first: start from the guest journey
- Reuse, buy, then build: build only to differ
- Cloud first: new workloads in the cloud
- Data as an asset: one governed source
- Secure by design: security in every change
- Simple: fewer platforms, fewer interfaces

## The target architecture has four layers
Layout: pyramid
- Experiences: stores, site, app and associate tools
- Business platforms: commerce, OMS, ERP, WMS, POS
- Data and integration: data platform, APIs, events
- Foundations: cloud, network, identity, security

## Value and fit set each application's path
Layout: matrix
- Invest: high business value, good technical fit
- Migrate: high business value, poor technical fit
- Tolerate: low business value, good technical fit
- Retire: low business value, poor technical fit

## Five moves modernize the estate
| Move | From | To |
|---|---|---|
| Integration | Point-to-point files | APIs and events |
| Data | Reports per system | One data platform |
| Infrastructure | Own data centers | Cloud platforms |
| Delivery | Annual projects | Product teams |
| Security | Network perimeter | Identity first, zero trust |

## The technology roadmap by quarter
Layout: timeline quarters
- Integration platform live: Jan 2027 to Jun 2027 (Integration)
- Data platform, phase 1: Mar 2027 to Sep 2027 (Data)
- Product teams for commerce: Apr 2027 to Jun 2027 (Delivery)
- Data center exit, wave 1: Jul 2027 to Dec 2027 (Infrastructure)
- Zero trust access: Sep 2027 to Mar 2028 (Security)
