# Product requirements summary

## Goals and non-goals
### Goals
- Members reorder in under ten seconds
- Reorders count towards rewards
### Non-goals
- Subscriptions (next release)
- Reordering for other people

## Who uses it
| User | Need | Success looks like |
|---|---|---|
| Member | Reorder favourites fast | Two taps from home screen |
| Store associate | See pickup reorders | Same pickup flow as today |
| Service desk | Help with a failed reorder | Order history in one view |

## Requirements by priority
| Requirement | Priority | Notes |
|---|---|---|
| Show past purchases | Must | Last 12 months |
| Reorder with saved details | Must | Default to last used |
| Remind when likely to run out | Should | Opt-in only |
| Reorder a whole routine | Could | Groups of products |
| Share a reorder list | Won't (this release) | Later |

## Non-functional needs
Layout: hexagons
- Fast: screen in under one second
- Available: same as checkout
- Secure: saved payment rules apply
- Accessible: meets the accessibility standard
- Measurable: every step tracked
- Supportable: service desk can see it

## Open questions
| Question | Owner | By |
|---|---|---|
| Which items cannot be reordered? | Merchandising | Mar 5 |
| How do points apply to reorders? | Loyalty | Mar 12 |

## Sign-off
- Decision: Requirements agreed for release 1
- Ask: Product, engineering and design leads sign
- Next step: Build starts next sprint
